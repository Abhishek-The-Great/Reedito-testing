# Reedito version and feature history

This file tracks Reedito product changes separately from the inherited Core
version. The repository root package is private and has no Reedito product
release version. Until a tagged release is created, new Reedito work is tracked
under **Unreleased**. Do not treat this ledger as proof that a feature is live.

Times use UTC. Older work is dated from `action.md`; exact times were not
recorded at the time.

## Current feature status

### Already present in the source

| Feature                           | Current behavior                                                                                                                                                                                                                                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Creator profiles                  | Staff author profiles and public author pages are part of the single-publication CMS.                                                                                                                                                                                                                                                |
| Staff author invitations          | Publication owners can invite staff authors; roles and permissions govern what each invitee can do. Invited writers publish to the same publication. This is the existing writer-access path, separate from reader membership signup.                                                                                                |
| Public creator signup             | Anyone can request an email setup link at `/reedito/join`; completed accounts receive the Contributor role and can draft in the shared publication. Publication editors retain publishing control. Reader signup remains a separate flow.                                                                                            |
| Moderation                        | Comment reports plus article/update reports, creator blocking, per-member limits, IP/member throttles for comment submissions and reports, and a moderator queue for Owner/Admin are active. These are rate-based abuse controls, not an ML/content spam classifier. Signup/account abuse controls still need production monitoring. |
| Publication recommendations       | Existing recommendation infrastructure is available; build on it rather than adding a duplicate recommendations service.                                                                                                                                                                                                             |
| Branded error fallback            | Built-in page handles 404 and common failure statuses; a theme-specific error template takes precedence when present.                                                                                                                                                                                                                |
| Article discovery and SEO         | Public author and tag archives, RSS feeds, XML sitemaps, canonical metadata, and schema.org article structured data are present in the inherited publishing platform. No AI-specific search ranking can be guaranteed.                                                                                                               |
| Publishing controls               | Scheduled publishing, private draft previews, and post revision history are present in Core/Admin.                                                                                                                                                                                                                                   |
| Server error reporting            | Sentry Core and Admin hooks exist; reports remain inactive until an operator configures DSNs and issue alerts.                                                                                                                                                                                                                       |
| Uptime reporting                  | Sentry Uptime Monitoring can check public URLs; no monitor or notification workflow is configured in this source.                                                                                                                                                                                                                    |
| Creator analytics                 | Admin `/community` shows the signed-in Author/Contributor's own published articles and metrics; the article table covers the latest 25 and referrals the latest five. Tinybird is required for read counts.                                                                                                                          |
| Federated short posts and follows | The optional ActivityPub app separately provides federated feeds, profiles, follows, and short-form social posts. Reedito first-party creator updates and reader follows are also available in the standard publication site.                                                                                                        |
| Reader community                  | Portal `#/portal/community/` includes a personalized article/update feed, creator/topic follows, recommendations, saved articles, and article likes/claps. Requires member sign-in.                                                                                                                                                  |
| First-party creator updates       | Authors/Contributors submit up to five 500-character updates per hour; a moderator must approve them before they appear in the reader feed.                                                                                                                                                                                          |
| Article saves and reactions       | A member can save an article and set one `like` or `clap` reaction per article. Stored separately from comments and ActivityPub.                                                                                                                                                                                                     |
| Community report/blocks limits    | Up to five reports per hour per member; up to 500 followed creators, 100 followed topics, and 100 blocked creators.                                                                                                                                                                                                                  |
| Weekly reader digests             | Opt-in weekly email with up to 20 recent public articles from followed creators/topics. Blocked creators are excluded; no message is sent when there are no new matches. Requires a configured site email provider. See `docs/features/series-and-reader-digests.md`.                                                                |
| Article series                    | Use one public tag named `Series: <title>` on each related post. Existing tag archives provide the series landing page; Portal feed cards link to it. Ordering follows publication date; manual chapter order is not provided.                                                                                                       |

### Not implemented or excluded from this release

| Feature                           | Intended behavior                                                                                                                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Paid membership                   | Monthly or annual reader subscriptions grant access to paid articles/newsletters; requires working recurring billing and verified entitlement updates.                                                                   |
| One-time tip                      | A reader makes a single support payment without starting a recurring plan.                                                                                                                                               |
| Gift membership                   | A buyer purchases a defined access period for another recipient, who redeems it through their account/email.                                                                                                             |
| Trial and discount                | A creator offers temporary access or a code/offer that changes the checkout amount or initial billing period. Gateway capabilities and renewal edge cases need explicit tests.                                           |
| Payments implementation status    | Payment gateway work was explicitly excluded from the current request. Checkout, provider webhooks, refunds/cancellations, and paid entitlements remain disabled/unimplemented. API keys alone do not activate payments. |
| Creator payouts and platform fees | Requires a marketplace-capable provider, creator identity/KYC onboarding, payout and refund handling, and tenant-safe accounting. Not implemented by the current single-publication model.                               |
| Separate creator publications     | Not implemented. Reedito still runs a shared single publication; this work does not add multi-tenant data isolation or cross-publication discovery.                                                                      |

## Release rules

- Record application features only after code and relevant tests have landed.
- Use the version actually released/tagged, not an assumed release number.
- Record exact UTC time for changes made after this ledger was introduced.
- For removals, explain whether a feature was removed from the product, disabled by
  default, or only hidden in the UI; preserve historical data details.
- Promote `Unreleased` to a semantic version when the Reedito release process and
  package manifests are ready. The existing Core version does not substitute for
  this product release tag.
